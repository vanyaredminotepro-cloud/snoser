# Гайд: как подключить проект к хостингу Railway.app

Этот гайд описывает пошаговый деплой бота из этого репозитория в Railway.

## 1) Подготовка

Перед деплоем убедитесь, что у вас есть:
- аккаунт на [railway.app](https://railway.app),
- репозиторий с этим проектом на GitHub,
- Telegram credentials:
  - `TG_API_ID` (или `API_ID`),
  - `TG_API_HASH` (или `API_HASH`),
  - `TG_BOT_TOKEN` (или `BOT_TOKEN`).

В проекте уже есть:
- `Dockerfile` для сборки контейнера,
- `railway.json` с типом сборки `DOCKERFILE` и политикой перезапуска,
- стартовая команда `python -m app.main`.

## 2) Подключение репозитория к Railway

1. Откройте Railway → **New Project**.
2. Выберите **Deploy from GitHub repo**.
3. Подключите GitHub-аккаунт (если ещё не подключён).
4. Выберите репозиторий с этим проектом.
5. Railway автоматически запустит сборку через `Dockerfile`.

## 3) Настройка переменных окружения

В Railway откройте ваш сервис:

- **Variables** → добавьте минимум:
  - `TG_API_ID`
  - `TG_API_HASH`
  - `TG_BOT_TOKEN`

Рекомендуется также добавить (при необходимости вашего сценария):
- `ADMIN_ID`
- `TARGET_CHANNEL`
- `ADMIN_USERNAME`
- `SESSION_NAME`
- `SQLITE_PATH`
- `LOGS_DIR`
- `PORT`
- `HEALTHCHECK_ENABLED`
- любые другие переменные, которые вы используете в `app/config.py`.

> Важно: не храните секреты в репозитории. Используйте только Railway Variables.

## 4) Проверка Deploy/Runtime

После первого деплоя:

1. Откройте вкладку **Deployments** и убедитесь, что сборка прошла успешно.
2. Откройте **Logs** и проверьте, что приложение стартовало без ошибок.
3. Убедитесь, что health endpoint отвечает `ok` на порту `PORT`.
4. Проверьте, что бот отвечает на `/start` и видит нужные источники.

Если что-то не стартует, сначала проверяйте:
- корректность `TG_API_ID/TG_API_HASH/TG_BOT_TOKEN`,
- права бота в канале,
- наличие корректного `ADMIN_ID`.

## 5) Автодеплой при изменениях

По умолчанию Railway делает redeploy после новых коммитов в подключённой ветке.

Рекомендуемый workflow:
1. Вносите изменения локально.
2. Делайте commit + push в GitHub.
3. Railway автоматически запускает новый deployment.
4. Проверяйте логи после каждого деплоя.

## 6) Полезно знать по этому проекту

- Хранилище по умолчанию — SQLite. Для простых сценариев подходит, но хранение на ephemeral-диске Railway может теряться при пересоздании контейнера.
- Для production-нагрузки рекомендуется вынести persistent-данные во внешний сервис (например, PostgreSQL/managed storage) или подключить persistent volume.
- Политика рестартов уже задана в `railway.json` (`ON_FAILURE`, `max retries = 10`).

## 7) Краткий чек-лист

- [ ] Репозиторий подключён через **Deploy from GitHub repo**
- [ ] Переменные `TG_API_ID`, `TG_API_HASH`, `TG_BOT_TOKEN` добавлены
- [ ] Deploy successful
- [ ] В логах нет критических ошибок
- [ ] Бот отвечает в Telegram
